- Date captured: 2026-06-29
- Base package: `openclaw@2026.6.6`
- Live target: `/opt/homebrew/lib/node_modules/openclaw/dist/monitor-DLQu0UP3.js`
- Patch file: `patches/openclaw-2026.6.6/signal-durable-inbound-queue.patch`
- Workspace source commit: `dd64846 Record OpenClaw Signal ingress durability patch`
- Patch SHA-256: `b8873162f541bc522aaf18aadb59acbaf46f0b85477c472c2b3f3ed72b89b788`

### Problem

Signal inbound events were handed from the Signal stream into an in-memory task runner. Session recording happened later in the handler. If the gateway restarted while an event was pending or before dispatch finished, the inbound message could be lost.

### Fix

The Signal monitor now creates a durable append-only queue under OpenClaw state before dispatch:

```text
~/.openclaw/channel-inbound-queue/signal/<account>/events.jsonl
```

On monitor startup, pending events are replayed before the live stream loop starts. Each event records `enqueued`; successful handling records `processed`.

## parent-fork-dynamic-context-tokens

- Date captured: 2026-07-05

- Patch file: `patches/openclaw-2026.6.6/parent-fork-dynamic-context-tokens.patch`
- Patch SHA-256: `5cf978e895a90ef700ed5f9f6eabfe3ff62d5ad4516137f910c98fd58a355d1e`

### Problem

OpenClaw's `context="fork"` parent-size check used a hardcoded `DEFAULT_PARENT_FORK_MAX_TOKENS = 100000`. A large-context provisioned-agent failure hit this exact path: a parent session around `166533` tokens was treated as too large for fork despite the active brain and generated agent config supporting about `1010000` context tokens.

### Fix

The fork decision now resolves its max parent budget dynamically:

1. Parent session `contextTokens`
2. Parent session model/provider resolved against current runtime config
3. `agents.defaults.contextTokens`
4. Legacy `100000` fallback only when no session, model, or config budget is available

Subagent, threaded reply, and realtime consult fork call sites now pass runtime config into the shared fork decision helper.

### Verification

`scripts/verify.sh` checks the dynamic resolver symbols, config-aware call sites, and JavaScript syntax for all touched files. A direct module-level regression should also prove a `166533`-token parent with `contextTokens=1010000` forks with `maxTokens=1010000`, while a parent with no session/model/config context still falls back to `100000`.

3. a normal macOS permissions check using three successful tool calls and one

### Problem

Finn was asked to queue ten paper-writing subagents. After every successful
`sessions_spawn`, OpenClaw injected guidance ending with an unconditional
instruction to reply `NO_REPLY` when a completion event arrived after a final
answer. The local Qwen parent generalized that instruction to the current
original direct turn and attempted `NO_REPLY` after only two accepted workers.

The fail-closed debug hook prevented silent delivery, but it did not recognize
counted subagent requests and rebuilt evidence from the latest hidden
continuation message. Earlier accepted spawns therefore disappeared from the
hook's count.

### Fix

- constrain `NO_REPLY` to a later completion-event turn after a visible final
  answer has already been delivered;
- explicitly require every user-requested worker to be spawned before yielding
  or finalizing;
- recognize numeric and common word-form worker counts in queue/spawn requests;
- count successful `sessions_spawn` results by tool-result id across hidden
  continuations;
- anchor evidence to the original behavioral request;
- reject `NO_REPLY` on a direct counted-fanout turn, including after all workers
  have been accepted, until a visible acknowledgement is returned;
- record accepted spawn count in redacted finalization diagnostics.

The concurrency limit remains unchanged. Finn may accept and durably queue more
workers than the two local-model slots that execute simultaneously.
